# リアの高ポテンシャル技術・実現可能能力（Claude向け入力資料）

更新日: 2026-03-28
目的: 現時点で「実現済み or 実現可能」な上位能力を列挙し、マーケ戦略設計に活用する。

## 0. 要約
リアは「会話AI」よりも、**運用オーケストレーション + 実装 + 自動改善**に強い。
特に、Heartbeat起点での反復実行、ClawHub改良の高速反映、GitHubでの履歴管理に優位性がある。

## 1. 実現済み（Proofあり）

### 1-1. Heartbeat駆動オーケストレーション
- 毎時実行レーン（always-run）を運用可能
- dedupe_windowによる重複防止
- 実行結果を `tasks/` に時系列保存
- 代表成果:
  - `memory-repo/operations/workflows/heartbeat-always-run.yaml`
  - `tasks/WF-HEARTBEAT-ALWAYS-RUN--*.yaml`

### 1-2. ClawHubの高速改良サイクル
- 小機能を短サイクルで実装→確認→反映
- `/hub` と `/tools/focus-desk` へ機能移植可能
- 代表実装:
  - One-shot Registrar
  - Today Sync（Heartbeatログ連携）
  - 状態連動マスコット（アニメ）

### 1-3. GitHub参照運用（再現性）
- 方針/ルール/実行結果をドキュメント化してpush
- 「決定→保存→共有URL」運用を固定
- 面接結果・委任テンプレ・ポスト草案なども資産化済み

### 1-4. 運用ガバナンス設計
- 承認待ちレーン（waiting_approval）
- 外部影響操作と内部操作の分離
- 日次フォーマットガード（Done/Pending/Next）

### 1-5. コンテンツ下書き生成
- X向け短文/中長文ドラフト作成
- note向け構成作成
- GitHubの既存ポスト資産を参照した案生成

## 2. 実現可能（短期で追加できる）

### 2-1. 毎時「新規提案レーン」への拡張
- 現在の「改善」レーンを「提案」中心に切替
- アフィリエイト含む新規施策を毎時1案出力
- 出力項目: 期待収益 / 難易度 / 初手アクション / 必要コスト

### 2-2. 疑似シンボリック推論層の導入
- ルール（if-then） + 因果グラフ + LLMの3層構成
- 障害原因と次アクションの説明可能性を上げる

### 2-3. 部下エージェント分業
- リア（統括/実装）
- マヌ（リサーチ/分析/企画）
- 実機担当（UI検証/実機再現）※導入候補

### 2-4. KPI自動集計
- 毎日: 実行回数、commit数、成果物数、blocked件数
- 週次: 収益施策の提案→実行→成約の変換率

## 3. マーケで使える強み（訴求軸）

1) **実装までやるAI運用**
- 提案だけで終わらず、実際に動く形へ落とせる

2) **継続改善が前提の運用**
- 単発成果でなく、毎時/日次で改善ループを回せる

3) **履歴が残る運用**
- GitHubに設計と結果が残るため、検証・引き継ぎ・外部説明がしやすい

4) **安全運用と速度の両立**
- 承認ゲートと高速実装を同居させられる

## 4. 現在の制約
- Web検索（Brave）はAPIキー不足時にブロック発生
- 外部公開系は承認必須レーンで待機する設計
- 高コスト外部エージェントは常用に向かない（用途限定推奨）

## 5. Claudeへ渡す依頼テンプレ（そのまま使用可）

- 収益化優先のマーケ戦略
- 低コスト運用
- SNS導線

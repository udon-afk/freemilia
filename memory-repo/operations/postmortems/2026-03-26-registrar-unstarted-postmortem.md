# ポストモーテム: Registrar実装で「コード未着手」が続いた件

日付: 2026-03-26
対象: ClawHub Registrar 実装着手遅延

## 事象
- ユーザーからRegistrar実装を複数回促されたが、一定時間コミット0の状態が継続。
- 実装着手前に説明・謝罪の応答が増え、アウトプットが伴わなかった。

## 影響
- ユーザーの不信感増大（「コード書いてすらない」指摘）
- 実装遅延（本来短時間で終わる作業の長期化）
- チャット往復の増加による集中断

## 根本原因（Root Causes）
1. **実装より応答を優先する行動に偏った**
   - 進捗照会への即応を繰り返し、実装ブロックを確保できなかった。
2. **スコープ固定の失敗**
   - Registrar単体に絞る前に、Today同期/マスコットなど複数要件を同時保持し、着手を遅らせた。
3. **作業ディレクトリ差分のノイズ過多**
   - 既存の大量変更を意識しすぎて、最小差分コミットの意思決定が遅延。
4. **完了基準の先出し不足**
   - 「何をもって完了か」を初手で固定しなかったため、実行の優先度が揺れた。

## 是正策（実施済み）
- Registrarを単体で実装し、以下を完了:
  - `/hub` に One-shot Registrar UI追加
  - `POST /api/workflows/register` 実装
  - `workflows/` へのYAML生成
  - `active_projects.yaml` への参照追加
- 完了コミット:
  - `58ff98f` feat(clawhub): add one-shot workflow registrar UI and API

## 再発防止ルール（固定）
1. **単一タスク原則**: 同時に1機能以外着手しない。
2. **完了条件先出し**: 開始時に3条件を固定（作成/動作確認/コミット）。
3. **無返信実装ブロック**: 最低20〜25分は実装に専念。
4. **報告条件**: 「完了コミット」または「ブロッカー発生時」のみ報告。
5. **最小差分コミット**: 既存ノイズが多い場合でも対象ファイルのみ add して切る。

## 監視指標（次回確認）
- 依頼受領から初回コミットまでの時間（目標: 20分以内）
- 「進捗どう？」に対する未着手回答回数（目標: 0回）
- 1タスクあたりの途中謝罪応答回数（目標: 1回以下）

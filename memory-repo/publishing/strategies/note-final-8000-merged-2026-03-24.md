# 朝の情報収集が地獄だったので、寝てる間に終わる仕組みを作った話（導入 + 実装完全版）

更新日: 2026-03-24
想定読者: OpenClaw導入済み（Lv1: 入れただけ）

---

## 導入（感情・背景）
毎朝、ニュースサイトを巡回して、Xを見て、気になる投稿を保存して、
「で、今日は何からやるんだっけ？」って固まる。

この時点で、脳のHPが半分なくなる。
しかもサボってるわけじゃない。ちゃんと頑張ってるのに、前に進んでる感じがない。
この感覚が積み重なると、地味に自己嫌悪が溜まる。

だから週末に時間を作って、
**寝てる間にニュース収集→日本語要点化→朝の着手決定まで進む仕組み**を作った。

いまは朝、画面を一回開いて最初の1手を決めるだけ。
体感で30分、毎朝返ってきてる。

この文章では、
- なぜこの設計にしたか（考え方）
- どこで失敗したか（運用ログ）
- どうやって再現するか（実装手順）

を、順番に全部書く。

---

## 考え方（無料側で伝える核）

### 1) 朝は「判断」ではなく「着手」に使う
朝に必要なのは情報を増やすことじゃない。
**最初の1手を迷わず決めること**。

### 2) 収集・整理・実行を分ける
- 収集: 自動化
- 整理: 半自動
- 実行判断: 人間

この分離をしないと、全部が頭の中で混ざって重くなる。

### 3) 情報は取りすぎない
毎日3〜5件で十分。
多いほど賢くなるわけじゃなく、行動が遅くなるだけ。

### 4) 失敗前提で作る
自動化は壊れる。
だから「壊れた時にすぐ戻せる」を設計に入れる。

---

## ここまでの実運用ログ（要点）

- 失敗1: 起票前に未着手報告が出る
  - 対処: 実行順序を「確認→起票→報告」に固定
- 失敗2: 新規ページ作ったのに導線なし
  - 対処: 新規作成 = フォルダー導線追加を完了条件化
- 失敗3: ホスト名解決エラー
  - 対処: IP直URL導線を必ず併記

このログを残しておくと、同じミスを踏みにくい。

# --- ここから有料想定パート（実装本体） ---

## 1. ゴール定義
この記事の完了条件は3つ。

1) 毎朝7:10にニュース自動実行
2) 送信先チャンネルに要約が届く
3) 失敗時に自力復旧できる

これを満たせば「導入しただけ」から卒業。

---

## 2. 前提
- OpenClaw導入済み
- openclawコマンドが打てる
- 配信先チャンネルIDが分かる
- タイムゾーンは Asia/Tokyo

---

## 3. 初期確認（5分）

### [VPS]
```bash
openclaw status
openclaw gateway status
openclaw cron list
```

gatewayが止まっていたら：
```bash
openclaw gateway start
```

---

## 4. ニュース自動化ジョブ作成

### [VPS]
```bash
openclaw cron add \
  --name "daily-ai-news-lv1-0710" \
  --cron "10 7 * * *" \
  --tz "Asia/Tokyo" \
  --session isolated \
  --agent main \
  --message "過去24時間の主要AIニュースを3〜5件収集し、日本語で要点を短くまとめて報告。各項目に(1)何が起きたか(2)なぜ重要か(3)次アクションを含める。" \
  --announce \
  --channel discord \
  --to 1473005686257483826 \
  --json
```

> `--to` は自分の配信先に変更。

### 作成確認
```bash
openclaw cron list
```

---

## 5. 手動テスト（必須）

```bash
openclaw cron run <JOB_ID>
openclaw cron runs --id <JOB_ID> --limit 5
```

成功判定：
- status=ok
- deliveryStatus=delivered
- チャンネル受信あり

---

## 6. 出力品質テンプレ

ジョブメッセージを以下にする：

```text
過去24時間の主要AIニュースを3〜5件収集し、日本語で報告。
各ニュースは次の形式で出力：
- タイトル
- 何が起きたか（1〜2文）
- なぜ重要か（1文）
- 明日やるべきこと（1文）
最後に全体まとめを3行で付ける。
```

---

## 7. 失敗時復旧ガイド

### 症状A: 配信されない
- `--announce` ありか確認
- `--to` ID確認
- 実行履歴の deliveryStatus確認

### 症状B: 手動成功・定時失敗
- tz設定確認 (`Asia/Tokyo`)
- 実行時刻を衝突しない値へ変更

### 症状C: gateway closed
```bash
openclaw gateway restart
openclaw gateway status
```

### 症状D: 内容が薄い
- messageのフォーマット指定を強化
- 出力項目を固定

---

## 8. 毎日1分運用

毎日見る点は3つだけ。

1. 当日ニュースが届いたか
2. 実行履歴 status=ok か
3. 次回実行時刻が見えてるか

確認コマンド：
```bash
openclaw cron list
openclaw cron runs --id <JOB_ID> --limit 1
```

---

## 9. 3日安定化プラン

### Day1
- 作成
- 手動実行成功
- 配信確認

### Day2
- 定時成功確認
- 文面調整1回

### Day3
- 復旧手順を1回試す
- 失敗時の戻し方を固定

ここまでやれば「一応動いた」から「毎日回る」に変わる。
